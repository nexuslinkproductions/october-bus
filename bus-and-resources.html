October Desktop · Architecture

Bus & Resources

October’s bus is an evidence-driven collaboration runtime: a durable canvas graph in Electron main, one loopback MCP/hook server, provider-specific static adapters, and ephemeral authority minted for one PTY or chat execution. Presence, attachment, readiness, lifecycle, reachability, delivery, automation, and session recovery remain separate facts. This document also follows the bus’s real resource bill: helper processes, bounded collections, retries, timers, and connected browser/screen/document context.

0The contract now

The shortest accurate model is static discovery, ephemeral authority, durable work, fresh delivery evidence. The bridge may be installed for years; the power to act lasts only for one execution.

What persists

A provider may retain an October-owned command, fixed helper paths, hook/plugin definitions, and—only for Codex—the names of four environment variables. The canvas snapshot retains logical collaboration state: nodes, edges, summaries, read markers, directed messages, tasks, and coarse ownership revisions.

What expires

The live port, canvas/node binding, capability, hook credential, PTY epoch, foreground PID, launch id, session id, cwd, readiness evidence, active reservations, and private adapter contact are execution-local. Replacing the run retires its authority.

Code-grounded corrections to the audit narrative

The canonical audit says the unattended-chain backstop is 300 turns. Current main code is authoritative and clamps it to 200 in settings, IPC, and delivery-coordinator.ts; the renderer still declares a pre-hydration default of 300. Effective main-owned automation is therefore capped at 200.

The registry promises Codex only explicit-message-only completion. Separately, the stop-hook handler accepts Codex’s last_assistant_message and can relay an unambiguous correlated response. This page treats the registry as the advertised guarantee and the stop-hook relay as an implemented, provider-dependent completion path—not as permission to relabel Codex unconditionally.

2Orthogonal runtime state

There is intentionally no master “connected” bit. Each state answers one question, and a UI badge or delivery decision must use the state that answers its question.

FactQuestion it answersOwner / evidence

ReachabilityCan this machine’s agent bus reach the node now?Local binding readiness or remote/unknown; never inferred from presence

How an ordinary manually typed command joins

  1. An October-owned generic shell may receive a PTY-scoped identity, but its principal begins as unactivated-terminal.
  2. A normal provider command loads the static machine adapter. Its MCP initialize must present the minted capability and a recognized client family.
  3. Main freshly probes the PTY’s foreground process. The asserted provider must own input, have a real agent PID, and still match the same PTY epoch and bridge instance.
  4. Only then is the run promoted to user-terminal. The provider keeps a stable schema, but every consuming/mutating call re-reads authority.
  5. Positive run replacement or PTY teardown demotes/revokes the old run. A failed process query does not erase working readiness by itself.

This is why toolbar launch, auto-launch, restore, exact-id History Play, restart/reconnect, operation workers, and manual commands can converge without PATH interception or visible --mcp-config arguments.

Four adapter families

Machine adapters

Claude, Codex, Grok, Muse, Hermes, Pi, Cline, Kimi, Freebuff, and Goose use a static user integration, global plugin/hook, generated extension, or private ancestry handoff. Their ordinary command remains ordinary.

Folder-required adapters

Cursor, OpenCode, Gemini, Qwen, OMP, and Antigravity need a real project. October writes only their owned repo/workspace integration; a home-shell launch remains visibly detached.

Launch-private terminal

October Harness receives its built-in extension and execution capability only for the October-owned process.

Launch-private chat

DeepSeek receives a temporary private patch for one headless chat execution. It has no interactive terminal surface.

Why Goose stays pull-only

Goose status callbacks are emitted from detached threads and can arrive out of causal order. A stale waiting after thinking cannot prove that Enter is safe. The registry therefore keeps authenticated tools and explicit pull, but sets activeWake: none. A longer debounce would only make the guess slower.

4The durable canvas store

LocalBusStore is a main-process single writer with one JSON snapshot per canvas under userData/context-bus. A successful send crosses a synchronous durability boundary before the sender is told it was accepted.

StateWhat it carriesRetention / cap
nodesDisplay identity, kind, coarse status, ownership revision, coarse execution state; local overlays may add cwd/attentionCanvas lifetime; owner tombstones prevent stale resurrection
edgesWhole undirected peer set plus Lamport-style owner revisionReplaced as a set; cloud ingress accepts at most 1,000
summaries + readsLatest versioned turn digest and per-reader version markersOne durable latest summary/node; in-memory journal keeps 10/node
messagesVerbatim directed text, intent/correlation, expiry, delivery markers, attempts, peer-turn evidence200 pending maximum; delivered rows older than 24 h pruned; expiry ≤30 days
tasksShared open/claimed/done board with deps and Lamport edit revision100 unreferenced done rows; open/claimed and referenced deps are retained
runtime mapsOpen reservations, blocking waits, local overlays, summary journalProcess-local; teardown/recovery owns cleanup

Ordinary summary/read/task churn uses a 400 ms coalesced flush. Message acceptance instead writes immediately: temporary file → file fsync → atomic rename → directory fsync on POSIX. If that fails, the in-memory append is rolled back and the send fails honestly. On Windows, atomic rename is the strongest portable directory-entry guarantee exposed here.

The reservation protocol

Ambient summary/read/task advances ride beside a reservation but remain in memory: a crash may repeat a digest, never a protected directed message. Active delivery reserves at most one request-bearing message so a provider result cannot be correlated to an ambiguous batch.

5Wake, delivery & reply completion

The coordinator owns the obligation to keep trying; deliverTerminalInbox owns the authority to type. A retry can re-evaluate evidence, but it can never create permission.

One directed terminal delivery, end to end

  1. Accept durably. Resolve only connected recipients, create one row per target, and fsync before returning success.
  2. Require policy and directed work. Automation must be enabled for this canvas/node, below the main cap, and pendingGeneration() must contain a deliverable directed message.
  3. Capture authority. Snapshot local owner id/revision and the exact PTY binding, harness, epoch, readiness, and user-input provenance.
  4. Probe the foreground. Main queries the process tree. A shell, unknown input owner, wrong harness, timeout, error, replaced PTY, or changed owner fails closed.
  5. Check human and provider state. Needs-input/permission state blocks. A trusted working signal blocks for up to 15 minutes. Quiet-heuristic rows require 800 ms without output unless a narrowly declared first-turn nudge exception applies.
  6. Recheck immediately before exposure. The same foreground process, owner revision, binding, epoch, attention, lifecycle, and user-input facts must still hold after every await.
  7. Reserve and paste. Mark reserved, build provider-aware framing, mark staged, and bracketed-paste the text.
  8. Delay and recheck. Wait 350 ms so the TUI ingests the paste, re-probe again, then mark submitted immediately before writing carriage return.
  9. Commit. Only after Enter is written does the store set delivery/read markers. A persistence failure quarantines the submitted attempt instead of duplicating it.
Content-free first-turn wake

Codex and Grok may receive one pre-readiness nudge; Muse may receive that plus one repaint-safe first-turn nudge. The latch is bound to node, canvas, PTY epoch, and backlog generation. Human input, consumption, lifecycle progress, epoch replacement, or teardown retires it.

Coordinator liveness

Message arrival, binding-ready, turn-end, input-resolved, policy change, renderer request, and cloud merge kick delivery immediately. Deferrals with a time hint get one replacing timer per node; all other pending work is revisited by a 20 s unref’d sweep.

Message intent and the return path

message_peer has protocol intent, not prose heuristics: notify is the default, request opens one correlated reply obligation, and response must name its responseTo. The legacy expectsReply flag remains a request alias. Expiry is optional and capped at 30 days.

6Connected resources are pointers, not authority

A terminal can be wired to a browser, screen, or document on the canvas. October mirrors that graph as bounded descriptive context; the descriptor tells the model what exists, while the corresponding tool rechecks whether the live main-process edge still authorizes access.

ResourceDescriptor shown to the agentAuthorization that remains separate
BrowserCanvas browser id and optional current URL; explicitly names October browser toolsBrowser registry resolves a currently connected local webview for this requester
Web / phone screenTitle, route, framework, absolute local project path, optional source file and preview URLDescriptive only; phone context explicitly grants no simulator-control authority
DocumentTitle, text/markdown format, byte count, update time, root id, relative path, document idread_connected_documents rechecks the live edge and reads a bounded snapshot; metadata grants no arbitrary path access

The privacy switch Share connected resources with agents controls the mirror. Turning it off sends a full empty replacement. Main accepts at most 128 terminal contexts and 32 unique resources per node; document descriptors are rejected above 100 KiB, control bytes are normalized, and screen project paths must be absolute. Snapshots, leases, and acknowledgements are memory-only and reset at bus teardown.

Current rollout boundary

Only Claude’s authenticated pre-prompt hook may lease passive resource pointers today. Codex and every other harness remain pending until their native prompt-assembly contract is proved. This is independent of whether they can call browser or document tools explicitly.

8Multiplayer & security boundaries

Cross-device collaboration synchronizes logical state, not the right to drive another machine’s terminal. Execution authority stays where the process lives.

May cross the cloud boundaryMust remain device-local
Node id/kind/display name, owner id/revision, coarse execution stateCapability values, hook tokens, bridge instance, binding id
Edges and owner-scoped node tombstonesPTY PID/epoch, foreground process evidence, input provenance
Versioned summaries and per-reader markersCwd, exact session id, transcript path, account provenance
Directed message text, intent/correlation, delivered/uncertain markersReservation attempt stage, peer-turn adapter evidence, local readiness
Shared task board and Lamport edit revisionsAttention prompt text, diagnostics, connected-resource snapshots

Ingress is treated as untrusted: objects are bounded to 500 records, edges to 1,000, text fields to 100 KiB, and invalid children are dropped independently before merge. Main refuses a remotely owned node before minting a local capability or spawning its PTY. Remote nodes report remote/unknown reachability until the owning machine supplies real runtime evidence.

Execution security

Routing headers are labels. A 32-byte random execution capability is the credential; comparison is timing-safe, and long-running tool leases recheck it after awaits. Old instances cannot demote or act for a replacement run.

Storage security

POSIX private artifacts require owner/type/symlink/mode validation. Windows private storage uses a protected current-user-only DACL with independent read-back and foreign-principal rejection. Ambiguity fails closed.

Privacy invariants

  • Analytics may record coarse harness, state, defer reason, transport, and outcome—but not node/canvas ids, command arguments, message text, paths, credentials, PIDs, or session ids.
  • Content-free diagnostics dedupe repeated defer reasons and bucket malformed body sizes instead of logging bodies.
  • Renderer display metadata cannot grant process ownership, principal role, or capability.
  • Foreign provider configuration is preserved; October refuses the collision rather than adopting, rewriting, or deleting it.
  • Outside-October launches remain inert and cannot dial a stale October process.

The adapter helper is not a second Electron app and does not load October’s module graph. It is a private Node runtime executing a generated zero-dependency script. Its per-request stdout queue is capped at 4 MiB; if the provider stops reading, the helper ends the transport rather than growing without bound.

Known shape, not hidden as a cap

The store cache has no LRU over canvas ids touched in one app process. Resource acknowledgements are keyed by execution and are removed when the node is forgotten or the bus resets. Open/claimed tasks also have no hard count cap because dropping live dependency state would corrupt the board. These are lifetime-bounded by product usage and teardown, not by an arbitrary eviction rule.

10Migration, recovery & teardown

River’s mixed HTTP/stdio failure made configuration ownership part of the runtime contract. Upgrade is exact, backup-first, and fail-closed around foreign bytes.

Startup convergence

  1. Reset private process ancestry state and sweep orphaned ownership/private launch artifacts before restored PTYs can register.
  2. Inspect only validated profiles and October-known project roots—normal home, managed CODEX_HOME profiles, and bounded trusted roots; never crawl the whole home.
  3. Recognize exact historical October live-HTTP, launch-override, hook, and mixed transport shapes. Publish content-addressed recovery records before mutation.
  4. Recheck owner, file type, symlink state, current bytes, and expected ownership immediately before atomic change. A foreign field or ambiguous collision stops that provider’s migration.
  5. Prepare the private helper runtime once, then install static Claude, Codex, Grok, Freebuff, Goose, and Kimi integrations independently so one collision cannot break clean providers.
  6. Folder-required adapters are prepared as bounded per-repo launch transactions; normal shell start is never blocked on slow project storage.
Uninstall and downgrade

Cleanup removes only exact October-owned artifacts and can restore journaled original bytes. Existing equal recovery content is success; conflicting content is preserved. There is no live-URL fallback, PATH shim, blind overwrite, provider trust bypass, or user-identity special case.

The HTTP server allows at most one successful bind in a main process. A failed first bind can retry because no PTY inherited it; after a successful bind or explicit stop, the safe recovery action is restarting October. The bus generation increments independently of the port so caches cannot mistake an OS-reused port for the old runtime.
